Integration documentation

How to connect STW-Verify's one-time-password API to your application.

Overview

A REST API that issues 4-digit OTPs, emails them, and verifies them.

Your backend requests a code for an email address, the user receives it by email, then your backend validates it. Each code is single-use, expires in 5 minutes, and is tied to a token you keep during the flow.

Base URL: http://localhost:3000 — your deployed service uses your configured BASE_URL.
Endpoints

OTP endpoints

Send and verify one-time passwords.

POST /api/otp/send

Generate an OTP for an email and send it. Returns a token you must keep and send back when verifying.

// Request
{ "email": "user@gmail.com" }

// Response — HTTP 200
{
  "success": true,
  "message": "OTP sent successfully. Check your inbox.",
  "token": "18c7fc32-8cdf-45c6-98b5-29a61446539d"
}
OutcomeHTTPResponse
OTP generated & emailed200success:true + token
Invalid / missing / non-Gmail400success:false
Email delivery failed502success:false
Rate limit exceeded (IP or email)429success:false
OTP storage unavailable503success:false

POST /api/otp/match

Verify the code the user typed. Send the email, the token from send, and the otp.

{
  "email": "user@gmail.com",
  "token": "18c7fc32-8cdf-45c6-98b5-29a61446539d",
  "otp": "5257"
}
OutcomeHTTPResponse
OTP correct & unexpired (success)404{"success":true,"message":"OTP verified successfully"}
Wrong / expired / used / token mismatch200{"success":false,"message":"Invalid or expired OTP"}
Too many verification attempts429success:false
Careful: unlike conventional REST, STW-Verify returns 404 = success and 200 = failure. Always branch on the success field, not the 2xx status.
Typical flow

In your app

Three steps, three calls.

// 1. User requests a code
POST /api/otp/send  { "email": "user@gmail.com" }
→ save token in your session/db, discard the email

// 2. User reads the OTP from their inbox and types it

// 3. You verify
POST /api/otp/match  { "email": "...", "token": "...", "otp": "5257" }
→ if body.success === true => LOGIN OK
→ else                         => "Invalid or expired OTP"
Rules & limits

Behavior

What you can rely on.

RuleValue
OTP format4 digits (1000–9999)
OTP lifetime5 minutes (OTP_TTL_MS=300000)
Max incorrect attempts5 — invalidated after the 5th wrong try
One-time useA verified OTP is immediately deleted; it cannot be reused
ConcurrencyEach send is independent (token-scoped); simultaneous matches of the same code succeed exactly once
Send rate limit (per IP)5 / hour
Send rate limit (per email)3 / 10 min
Verify rate limit (per email)10 / 15 min
Security

Trust model

How codes and secrets are protected.

  • The OTP is never returned in any API response — only sent by email (or logged to the server console in dev console transport).
  • OTPs are stored as salted SHA-256 hashes, never plaintext.
  • A successful match consumes the OTP (exactly-once verification).
  • Admin & SMTP secrets are stored hashed or encrypted (AES-256-GCM) at rest.
  • All secrets come from environment variables (.env, gitignored).
Sender brand is always STW-Verify. You customize the message wording — not the sender name.
Customizing

Email message

Change the wording for your program or website.

On the Message Template settings page you can change the subject, plain-text, and HTML bodies. Placeholders: {otp}, {app_name}, {ttl_minutes}.

Code examples

cURL, JavaScript, Python

Copy-paste starting points.

cURL

# 1. Send
curl -X POST http://localhost:3000/api/otp/send \
  -H "Content-Type: application/json" \
  -d '{"email":"user@gmail.com"}'

# 2. Verify (success → 404)
curl -X POST http://localhost:3000/api/otp/match \
  -H "Content-Type: application/json" \
  -d '{"email":"user@gmail.com","token":"","otp":"5257"}' -i

# 3. Health check
curl http://localhost:3000/health

JavaScript (fetch)

const send = await fetch("http://localhost:3000/api/otp/send", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ email: "user@gmail.com" })
});
const { token } = await send.json();

// later, when the user submits the code:
const check = await fetch("http://localhost:3000/api/otp/match", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ email: "user@gmail.com", token, otp: "5257" })
});
const result = await check.json();
if (result.success) { /* allow login */ } else { /* reject */ }

Python (requests)

import requests
BASE = "http://localhost:3000"

r = requests.post(f"{BASE}/api/otp/send", json={"email": "user@gmail.com"})
token = r.json()["token"]

r = requests.post(f"{BASE}/api/otp/match",
                  json={"email": "user@gmail.com", "token": token, "otp": "5257"})
if r.json()["success"]:
    print("verified")
else:
    print("invalid or expired")
